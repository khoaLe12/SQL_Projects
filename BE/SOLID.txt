
1. Single Responsibility Principle: Every class should have as few reasons for modification as feasible, the classes listed below are considered to change for reasons
+ BaseRepository: modify system table get or require additional query methods.
+ IEntityRepository: change the base CRUD logic.
+ BaseService: change the base CRUD business logic.
+ UnitOfWork: modify transaction implementation (this class is intended to remain unchanged when additional repositories are added; the repository is resolved using Repository(Type) function).
+ BaseController: add methods for post-invoke and pre-invoke when invoking action methods, or handle more headers.
+ Address: change the data model.
+ AddressKey: the Address entity's key change.
+ AddressRepository: require additional queries for Address entity.
+ AddressServices: business logic update.
+ AddressController: provide more API endpoints.


2. Open-Closed Principle
+ IEntityRepository and EntityRepository: entity repository interface with its implementation, closed for modification but open for extension.
+ AddressRepository: extends from entity repository, add soft delete by overriding ExecuteDelete function
+ EntityKey: base class represent the key of entity, include common implementation of keys attachment to parameters.
+ AddressKey: inherit from the base class that redefine how to attach keys
